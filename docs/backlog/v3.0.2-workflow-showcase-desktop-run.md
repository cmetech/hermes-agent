# v3.0.2 Workflow Showcase Desktop Run Backlog

This backlog records deliberate follow-ups that are not part of the v3.0.2
catalog/showcase implementation.

## Coverage after v3.0.2

v3.0.2 closes the v3.0.1 L-A/L-B limitations by listing all digest-verified
bundled showcases and making two of five runnable through Desktop's standard
background admission path:

- Desktop-runnable: `approval-gate`, `resilience`;
- CLI-only: `ai-extensions`, `scheduling`, `laptop-diagnostic`.

The CLI-only classifications are intentional, not missing catalog coverage.

## Background scheduling from Desktop

**Candidate:** v3.0.3 or later

Design a real coordinator-executed schedule-creation operation that is
admittable through the background path. The design must settle:

- schedule-time input and defaults;
- the target workflow/package;
- exact schedule ownership and cleanup semantics;
- idempotency and concurrency behavior;
- honest outward-action/risk projection.

The current `scheduling` showcase remains CLI-only because cron creation,
`schedule_at`, and exact-ID/nonce ownership live in the `run_showcase` wrapper,
not in the bundled workflow package admitted by `POST /runs`.

## Desktop AI-consent and architecture pass

**Candidate:** v3.0.3

Before implementation, verify whether every meaningful `ai-extensions`
behavior lives in the workflow package or whether the CLI wrapper contributes
required orchestration. If the workflow package is complete, design a Review &
Run consent dialog that presents/captures the AI confirmation token and teach
`start_api_run` to verify it. If required behavior lives in the wrapper, treat
the work as an architecture change rather than assuming a dialog alone can
unlock the showcase.

The consent UX must receive its own threat model and adversarial review because
it authorizes genuine model cost and potential external data egress.

## Rich Desktop workflow inputs

`laptop-diagnostic` remains CLI-only until Desktop supports the legacy
file/text input contract without weakening immutable input snapshots,
redaction, size limits, or path handling.

## Independent-review follow-ups

The independent v3.0.2 adversarial review reported ten Low findings and seven
informational notes. Its three Medium findings were fixed before handoff; the
following lower-severity work remains explicitly deferred:

- wrap unexpected `CoordinatorStore.health()` exceptions into a typed
  pre-persistence admission refusal;
- document or warn on legacy name-only API selection when a user workflow
  shadows a showcase name;
- add an operator-visible signal that distinguishes an absent showcase bundle
  from a rejected/tampered distribution without exposing sensitive paths;
- evaluate cold-list shared-byte-budget seeding and verified-cache lock scope;
- consider pinning exact showcase membership from the authenticated manifest
  while retaining behavior-contract tests;
- derive disabled-Run copy directly from `run_support.reason`, and disable the
  catalog Run action immediately when compatibility is known false;
- place the existing showcase AI/evidence test files into an explicit gate or
  opt-out bucket;
- extend authenticated-byte snapshot parsing to the no-budget local CLI path;
  and
- deduplicate catalog input projection and normalize cosmetic trust-label
  casing.

The accepted five-row reservation within the 500-row catalog and the shared
bounded request-byte accounting are documented behavior, not bugs. The
independent report remains the authoritative finding register and evidence
record for these follow-ups.
