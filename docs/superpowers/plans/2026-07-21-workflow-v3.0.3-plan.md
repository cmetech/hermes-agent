# Workflow v3.0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Preserve
> RED/GREEN ordering and stop on any design stop condition.

**Goal:** Make all five verified showcases Desktop-runnable while preserving
v3.0.2 trust, idempotency, REST, offline, and recovery contracts.

**Architecture:** Extend the existing workflow plugin at its admission,
snapshot, scheduler, and Desktop edges. Keep authenticated package caching
context-free; derive compatibility/risk from runner plus runtime/tool-loop
capabilities; make the isolated worker own request-MCP startup and cleanup;
derive scheduling indexes from durable projection metadata.

**Tech stack:** Python 3.13, FastAPI/Pydantic, SQLite, pytest, Electron/React,
TypeScript, Vitest.

**Date:** 2026-07-21 (Revision 7 — final pre-implementation contract)
**Design:** `docs/superpowers/specs/2026-07-21-workflow-v3.0.3-design.md` (Revision 7)
**Branch:** `feat/workflow-v3.0.3` from `base` (post v3.0.2 merge)
**Status:** Approved for execution after Task 0 prerequisites

Revision 7 retains Revision 6 and closes the final real-worker MCP findings:
the worker explicitly starts and reaps request-carried MCP under one outer
cleanup boundary; capability includes the configured runtime/tool-loop mode;
`codex_app_server` fails closed; admission and coordinator share one immutable
production binding declaration instead of adding a new immediate-run terminal
state; authenticated input translation and raw-data isolation are placed at
the API boundary; and namespace rebuilds derive `scheduled_at` only from the
projection. This is the final design baseline; no additional
pre-implementation adversarial review is scheduled.

Strict TDD throughout: one focused failing test per behavior change, RED
confirmed via the repository's prescribed command, smallest GREEN, refactor
under green. Full base merge gate green at the end of every workstream.
Update `docs/upstream-customizations/workflow-orchestration.yaml` in every
commit touching a listed surface.

## Global constraints

- No consent endpoint, token, dialog, HMAC key, or caller-supplied capability.
- No new core model tool, generic-host workflow import, or `HERMES_*`
  behavioral environment variable.
- No package-MCP bridge into `codex_app_server`; classify that externally
  owned tool loop incompatible before execution.
- Existing unscheduled and non-AI start digests remain byte-identical.
- Legacy flat REST `values` remain accepted under their current bounded
  portable contract.
- Schedule identity is canonical in `run_metadata.schedule_at`; the SQLite
  column is derived only.
- No external network or billable inference in automated tests.
- Required node MCP fails before provider/model traffic; cron's optional
  profile-global MCP behavior remains unchanged.
- Every task ends with its focused tests, the relevant merge-gate selection,
  `git diff --check`, customization-ledger update, and an atomic commit.
